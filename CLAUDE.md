## What Redlining is

A dev-only overlay for Next.js 16+ apps. The developer clicks an element or draws a box in the running app, writes a note, and every annotation resolves to `file:line` + host element + React owner chain. The batch exports to `.redlining/annotations.md` (+ JSON, optional screenshot); a `/redline` slash command hands it to Claude Code, and any other coding agent reads the same file or the copied prompt. Redlining never edits code.

Node 24 (`.nvmrc`); tsdown needs ≥ 22.18. If `node -v` shows 22.12, a stale `/usr/local/bin/node` is shadowing Homebrew's — prefix with `PATH=/opt/homebrew/bin:$PATH`.

```sh
pnpm install
pnpm build        # packages/* via tsdown → packages/redlining/dist
pnpm test         # vitest across packages/*
pnpm lint         # eslint flat config at root
pnpm typecheck    # tsc per package; example runs `next typegen` first
pnpm format:check # prettier; docs/ is ignored (PRD is hand-formatted)

pnpm --filter redlining exec vitest run -t 'name'   # one test by name
pnpm --filter next-app dev                          # example app; needs a prior `pnpm build`
pnpm e2e                                            # Playwright; starts its own `next dev` on :3199, needs a prior `pnpm build`
pnpm e2e:webpack                                    # the @webpack-tagged scenarios again under `next dev --webpack` (:3198)
pnpm e2e:vite                                       # examples/vite-app through a real Vite dev server with the endpoint (:3197)
pnpm --filter redlining vendor-tokens               # re-vendor design tokens from the canon
```

The example app consumes `redlining` through `workspace:*` and resolves the built `dist/`, so rebuild the package before running or typechecking the example. `next dev` regenerates `examples/next-app/AGENTS.md` and `CLAUDE.md`; commit them rather than fighting them.

Three Playwright configs, one per server, because two Next dev servers cannot share one `.next`.

Build shape in `tsdown.config.ts`: `.` and `./next/route` are ESM-only with `platform: neutral`; `./next`, `./loader` and `./vite` are ESM + CJS (`.mjs`/`.cjs`) so `next.config` can load them either way; the CLI is ESM with no d.ts. The bundler strips `'use client'`, so the overlay entry re-adds it via `banner` — keep the overlay in its own config block for that reason. React is never bundled.

TypeScript 5.9 strict (not 7: typescript-eslint caps below 6.1), Vitest 5 in node environment, ESLint 10 flat + typescript-eslint + react-hooks + prettier-compat, Changesets (config written by hand; `changeset init` needs a TTY). Playwright lives at the root (`playwright.config.ts`, `e2e/`); Chromium was installed with `pnpm exec playwright install chromium`.

## Overlay conventions

- **Shadow DOM host.** `<Redlining />` renders a 0×0 absolutely positioned host with `data-theme` and portals the app into its shadow root. The host is at page origin, so `.rl-layer` children positioned in page coordinates (`pageRect`) scroll with the page; `.rl-fixed` elements (toolbar, panel, toast) are viewport-fixed. Host page pointer events are intercepted with capture-phase listeners on `document`, never with a covering layer, so `elementFromPoint` keeps working. Layouts must ignore the host (`layoutIgnoring`).
- **Styles are plain CSS on the vendored tokens**, not Tailwind (design-system divergence D4). The accent is red (D5): `brandCss` in `styles.ts` re-points the `--sbm-green` ramp after the vendored tokens; never edit the generated tokens and never use `--sbm-*` in components. The screenshot pin colour in `screenshot.ts` and `site.css` carry the same values by hand. `tokens.generated.ts` is produced by `scripts/vendor-tokens.mjs` from the canon; never edit it by hand. Overlay rules live in `styles.ts` under the `rl-` prefix.
- **Keyboard.** `?` toggles `HelpPopover` (in-package help with the docs links; keep its key table in sync with README and the guide). Letter hotkeys match on `event.code` (macOS Option+R types `®`). Editors inside the overlay stop propagation of Escape/Enter, because the window handler would otherwise see the same keypress after React has already committed the state change and close the overlay.
- **Extend mode.** While a select note is open the select layer stays mounted with `onExtend`; only Shift+clicks reach it, other page clicks are swallowed. `Draft.extra` becomes `Annotation.anchors` (primary first) on save; `Entry.extraElements` mirrors it for pins and must be stripped wherever `element` is (`toSession`, `saveEntries`).
- **Screenshot.** `captureScreenshot` lazily imports `html-to-image`, filters out the host, paints pins via `drawPins` (unit-tested with a recording canvas), returns pin-free crops per entry (`cropRect`), and refuses results over 7 MB so the route's 16 MB cap holds. Reference images are pasted into `NotePopover` (`image.ts` shrinks them to 1600px JPEG), live on `Annotation.refs` as data URLs, and the route writes them plus crops as `ref-N-i.*` / `crop-N.png` after `withAssetPaths` swaps the data URLs for paths in the Markdown and JSON.
- **Tweak mode.** `preview.ts` is the only code that writes to host elements: `snapshot` once, then `apply(el, changes)` resets and re-applies the whole list (undo = pop + apply). `from` is always the computed value first seen (`baseline` in the Inspector). Only longhands are written; nudges are previewed on the CSS `translate` property (so an existing `transform` survives) and export as "visual nudge" with `property: 'transform'`; several entries on one element are grouped by `previews.ts` and applied together from one snapshot; text edits need `canEditText`. Entries carry `preview` (the snapshot) and strip it wherever `element` is stripped. Re-apply after reload/HMR and reset on delete/clear go through the anchor when the element handle is gone. The Inspector must never cover the element (below → above → beside → clamp, clear of the toolbar corner). Its sections start collapsed with a one-line summary (`7 12 7 12`); e2e tests click `rl-section-<id>` before using a stepper. `cascade.ts` resolves value provenance DOM-only (winning rule → inherited → layout; a stylesheet `!important` beats a normal inline style, layered `!important` beats unlayered, but layer _order_ is not tracked) and `suggestClass` probes single-class rules; `Change.source`/`suggestion` feed `describe()`, so layout-derived sizes export as `auto (Npx, laid out by the parent grid) → …` with a warning. `framework.ts` detects the styling idiom (Tailwind 4 tokens → Tailwind 3 `--tw-*` → hashed CSS Modules classes → plain CSS) and `theme.ts` maps values to utilities from the theme tokens plus a static default table (`classFor`, `themeScale`); `suggestionFor` in the Inspector prefers an emitted class, then the theme; settings (`redlining:settings`) override the `framework` prop, which overrides the detection, and `Session.styling` carries the result into the export header and footer.
- **Click after hover.** `SelectLayer` keeps the hover target in a ref, not only state: a click can follow a mousemove before React commits.
- **Zero production bytes.** `package.json` exports `.` with a `production` condition → `dist/index.prod.js` (`Redlining` returns null); the component also checks `NODE_ENV`. Verified: a `next build` of the example has no overlay class names in client bundles; the floor is the `return null` stub the layout imports (~30 bytes), which only the consumer can remove.

## Design decisions that constrain code

These are settled in the PRD; do not reopen them without asking.

- **Zero production footprint.** `<Redlining />` returns `null` outside `NODE_ENV === 'development'` so it dead-code-eliminates; `withRedlining()` is a no-op outside `PHASE_DEVELOPMENT_SERVER`; the route handler refuses outside dev. CI will assert 0 bytes and no `data-rl` in `next build` output.
- **Loader decorates host elements only** (lowercase JSX tags) with `data-rl="<relpath>:<line>:<col>"`. Never decorate components — it leaks an unknown prop. Component identity comes from the runtime fiber walk instead.
- **Loader parses with `@babel/parser`, not SWC.** The PRD assumed `@swc/core` comes with Next; it does not (Next ships only its own native bindings behind an undocumented `parse`). `@babel/parser` is parse-only, pure JS, no native binaries, and never touches Next's SWC compile pipeline. `magic-string` writes the stamp and the source map and is **bundled into `dist/loader.*`** (it is ESM-only and rolldown's CJS interop hands `new` the namespace object). The map is passed to the bundler as an **object**: webpack's downstream SWC loader rejects JSON text.
- **Rules match by filename glob plus a path regex, not root-relative globs.** Turbopack's root follows the lockfile, so in a pnpm workspace `app/**` never matches `examples/next-app/app/…`. `withRedlining` registers `'*.tsx'`/`'*.jsx'` with `condition: { all: [{ not: 'foreign' }, { path: /(^|\/)(app|components|src)\/.*\.tsx$/ }] }` and a webpack `enforce: 'pre'` rule with absolute `include` dirs. Stamped paths are relative to `projectRoot` (`process.cwd()` at config time), passed as a plain loader option.
- **Resolvers never touch the DOM's geometry directly.** `anchorFor` and `resolveContainer` take a `Layout` (`rectOf`, `elementsFromPoint`); `domLayout(document)` is the real one and tests inject rects, because jsdom has no layout and no `elementsFromPoint`. Resolve tests opt into jsdom per file with `// @vitest-environment jsdom`; everything else stays in node.
- **`Anchor.file`/`line` are optional**, unlike the PRD §6 sketch, so a `selector-only` anchor is typed honestly instead of carrying an empty path. `box.childIndex` means "insert before child N"; `children.length` is "at end".
- **`withRedlining` returns a config function** so it can see the phase; rules exist only under `PHASE_DEVELOPMENT_SERVER`, and a function config passed in is composed, sync or async.
- **React internals are quarantined.** `__reactFiber$…` and `fiber._debugOwner` live only in `resolve/fiber.ts`, feature-detected, degrading to file:line-only when absent. Server-only subtrees have no client fiber: `owners` is `[]` and the anchor is still exact via `data-rl`.
- **Pure cores.** `src/resolve/`, `src/export/` and the loader `transform(src, filename) → { code, map }` are pure functions with no DOM or Next dependency, so they are unit-testable and formatters stay pluggable.
- **Overlay isolation.** Shadow DOM host; Tailwind compiled to a CSS string injected into the shadow root; no global CSS; when inactive only the `Alt+R` hotkey listener exists and no pointer events are captured.
- **Verify loop.** `verify.ts` checks an entry against the page with its preview reset (`verifyEntry`, injected reader); the route's `GET` returns `reply.md` (`createHandlers` → `{ GET, POST }`, `createHandler` keeps returning `POST`), `export/reply.ts` parses `## N · done|partial|skipped — text`, and `App` auto-verifies on open when the reply is newer than `redlining:saved[route]`. `redlining init` writes `export { GET, POST }` and notes old routes/commands.
- **Beyond Next.js.** `src/standalone.tsx` bundles React (`platform: browser`, `codeSplitting: false`, NODE_ENV fixed to development, no production stub) and auto-mounts from `<script data-redlining data-endpoint=…>`; `endpoint: false` or a 404/network failure makes Save download the files via `download.ts` (detached anchor, because the overlay's capture-phase click listener would cancel an attached one). The handler lives in `src/server/handler.ts` (`next/route` re-exports it); `redlining/vite` can serve it (`endpoint: true`, `serveRedlining` adapts connect requests). `resolve/owners.ts` tries React, then Angular's `ng` global, then Vue's `__vueParentComponent`. The e2e fixture `examples/next-app/public/standalone.html` loads the bundle copied by `e2e/global-setup.ts` (gitignored).
- **Route handler safety.** Writes only under `<projectRoot>/.redlining/`, path-validated per file (`inside()`), every posted session validated by `server/validate.ts` (positive-integer indices and crop keys, one level of `others`), cross-origin browser requests refused (`crossOrigin`: `Origin` must be this server, `Sec-Fetch-Site` same-origin; header-less requests pass), body capped in UTF-8 bytes (16 MB; screenshot ≤ 7 MB, crops ≤ 4 MB) and, in the Vite adapter, while streaming.
- **Peers.** `react` and `react-dom` ≥ 19 are required peers, `next` is optional (`peerDependenciesMeta`), so Vite and standalone consumers do not pull Next; only `dist/standalone.js` bundles React. `withRedlining` appends to a consumer's own `*.tsx`/`*.jsx` Turbopack rule (rule arrays) instead of replacing it. Interaction layers restore the body's previous `cursor`/`user-select` via `holdBodyStyle`.
- **Anchor fallback ladder** is `exact` → `ancestor` → `selector-only` (§8.5); the export must state which one applied.
- **`redlining init` is idempotent** and never touches `CLAUDE.md` (Next 16.3 manages its own block there).
- Open M0 spike (§8.3): the `_debugStack` path may replace the loader as default if it passes 20/20 sample elements incl. Server Components on 16.3 stable and canary. Until decided, the loader is the default.

## Release and publish

Everything ships from `packages/redlining`; the example app and the site are never published. Only the user publishes and pushes; Claude prepares the release and stops before `pnpm publish`, `git push` and `git push --tags`.

**The version is stepped automatically, never by the user at publish time.** Whenever a change to the published package lands (anything under `packages/redlining/src`, the CLI templates, `package.json` exports), Claude bumps `version` in `packages/redlining/package.json` and adds the CHANGELOG entry in the same change: patch for fixes and doc/link changes inside the package, minor for features. The user only runs `pnpm publish`. As a guard, `prepublishOnly` starts with `scripts/check-version.mjs`, which asks the registry and refuses a version that is already published, naming the next number; `pnpm --filter redlining check-version` runs it alone.

**Before `pnpm publish`, check the login.** `npm whoami` must print the user's name. A `401` there means the saved token in `~/.npmrc` has expired or been revoked, and npm then reports the publish as `E404 Not Found - PUT https://registry.npmjs.org/redlining` / `'redlining@X.Y.Z' is not in this registry`, which is not a package or version problem. Fix: `npm login` (browser flow, rewrites the token), then publish again. Other publish refusals have plain messages: `You cannot publish over the previously published versions: X.Y.Z` means the version in `package.json` was never bumped after the last publish (check `npm view redlining versions --json`); `ERR_PNPM_GIT_NOT_LATEST` or a dirty-tree error means pull or commit first. Diagnose read-only (`npm whoami`, `npm config get registry`, `npm view`), never by retrying the publish.

1. **Green first.** `pnpm build && pnpm test && pnpm lint && pnpm typecheck && pnpm format:check && pnpm e2e && pnpm smoke` (all with `PATH=/opt/homebrew/bin:$PATH` if `node -v` is not 24). `pnpm smoke` packs the tarball and imports every entry from a bare consumer, ESM and CJS; it is what catches an extensionless deep import or a missing export condition. Never tag on a red run.
2. **Version from the commits since the last tag**, reading the diffs, not the messages: pre-1.0, `feat` bumps the minor, `fix` the patch, a breaking change bumps the minor and says so in the changelog. Check `npm view redlining versions --json` before choosing: a number that is already on npm can never be reused, and a tag that points at a published version is never moved (0.4.0 was once re-pointed by mistake and reverted).
3. **Changelog by hand** in `packages/redlining/CHANGELOG.md`, then `pnpm site:changelog` to regenerate `site/changelog.html` (the public version history; CI fails when it is stale, and the tag date only appears after step 4, so run it again after tagging): a `## X.Y.Z` section with `### Minor Changes` / `### Patch Changes`, one bullet per user-visible change in the wording the README uses. Changesets is installed (`.changeset/config.json`) but `changeset version` is not the workflow; the file is written directly and the version bumped in `packages/redlining/package.json`.
4. **Release commit and tag.** `chore(release): X.Y.Z` containing only the changelog and the version bump, then an annotated tag `vX.Y.Z` whose message is the release notes (`git tag -a vX.Y.Z -F -`). Nothing else goes into that commit.
5. **Publish (user).** From `packages/redlining`: `pnpm publish` (npm 2FA prompts for the OTP). `prepublishOnly` rebuilds `dist/` and copies `README.md` and `LICENSE` in; `postpublish` removes them again, so the package directory stays clean in git. `files` limits the tarball to `dist`, `README.md`, `LICENSE` and `CHANGELOG.md`; `publishConfig.access` is public; `engines` requires Node ≥ 22.18 (tsdown). Then `git push && git push origin vX.Y.Z`.
6. **Verify from the registry**, not from the working tree: `npm view redlining@X.Y.Z version dist.tarball`, and in a scratch consumer `pnpm add -D redlining@latest` followed by imports of `redlining`, `redlining/next`, `redlining/next/route`, `redlining/loader`, `redlining/vite` and `redlining/standalone`. Consumers on `^0.x` do not pick up a new minor with `pnpm update`; tell them `pnpm add -D redlining@latest`.

What the tarball must contain, and what it must not: every `exports` entry resolves to a file under `dist/` with `import`, `require` (where CJS exists) and `types`; `.` also has the `production` condition pointing at the null stub; `magic-string` is bundled into `dist/loader.*`; React is never bundled except in `dist/standalone.js`; no `examples/`, `site/`, tests or source maps of the example. `pnpm smoke` asserts most of this; `npm pack --dry-run` in `packages/redlining` shows the rest.

## Docs site

`site/` is a static site with no build step: five hand-written pages (`index`, `getting-started`, `guide`, `format`, `help`) plus `changelog.html`, which `scripts/site-changelog.mjs` generates from the package changelog and the tag dates (never edit it by hand), sharing `site.css`, which hand-copies the light-theme silverballmania values. It is served at https://redlining.deep-thought.rocks by Vercel from `vercel.json` at the repo root (no install, no build, `outputDirectory: site`, clean URLs); the DNS is a Cloudflare CNAME `redlining` → the project-specific `*.vercel-dns-016.com` target, DNS-only (grey cloud), so Vercel issues the certificate; There is no GitHub Pages deployment: the Pages workflow failed on every push while the repository was private and was removed on 2026-09-08; Vercel is the only deploy. The site navigation, README and package.json link to the repository at its organisation address. The silverballmania mark in its canon black-and-white variant (`silverballmania-mark-black.svg`, never recoloured beyond the canon's variants) is the header logo and favicon set under `site/favicons/` and `site/images/`; the PNGs and the `.ico` were rendered from that SVG with a Chromium script, so re-render rather than hand-edit when the canon changes the mark. The getting-started page carries the agent setup prompt (`#agent`, copy button with a select-text fallback); if the setup steps change, update that prompt, the README section that points at it, and `redlining init` together. Install commands are shown per package manager (npm first) and the agent setup prompt tells the agent to follow the lockfile and never names one manager as _the_ example, because a consumer's agent once ran pnpm in an npm repository. Keep the key table, options and format reference in sync with the README and the overlay; the link/anchor check is a shell loop over `href`/`src`/`id` (see the commit that added the site).

## Design system

The overlay adopts **silverballmania** v2.0.0 from `~/Repositories/design-systems/silverballmania/`. `.claude/design-system.json` is the single source of truth for the assignment, theme policy (light default), divergences and open gaps; read it before styling anything in `src/overlay/`. The canon's `SKILL.md` and `README.md § Design tokens` carry the rules. Components use only `--color-*` semantic tokens, never `--sbm-*` raw values.
